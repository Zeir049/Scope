# Glitch — 피그마 프로토타입 vs 백엔드 구현 갭 분석

> 비교 대상: 피그마 프로토타입 `프로토타입 최종 (팝업)` 전체 화면 ↔ 현재 백엔드(`C:\glitch_backend`)
> 작성일: 2026-06-29

---

## 한 줄 결론

서비스의 **핵심 루프**(회원 → 드라이브 → 회차 업로드 → 분석 → 검토 → 저장 → 캐논 6탭 조회)는
화면과 거의 1:1로 모두 구현돼 있다. 부족한 부분은 대부분 **주변·보조 기능**과
**프로젝트 메타데이터** 영역이다.

---

## 구현 완료 (화면 ↔ API 매칭됨)

| 화면 | 대응 API | 상태 |
|------|----------|------|
| 로그인 / 회원가입 / 로그아웃 | `POST /auth/login`·`register`·`logout` | ✅ |
| 내 드라이브 (검색 + 페이지네이션) | `GET /projects?page=&q=` | ✅ |
| 새 프로젝트 생성 | `POST /projects` | ✅ |
| 프로젝트 진입 / 삭제 | `GET /projects/{id}`, `DELETE /projects/{id}` | ✅ |
| 원문 업로드 + 상태칩(저장됨/신규) | `GET /projects/{id}/chapters`, `POST .../chapters` | ✅ |
| 분석 실행 (캐논 대조) | `POST .../chapters/{cno}/analyze` | ✅ |
| 모순 하이라이트 / 결과 폴링 | `GET .../chapters/{cno}/result` | ✅ |
| 저장하기 (캐논 병합) | `POST .../chapters/{cno}/save` | ✅ |
| 자료정리 6탭 (세계관/인물/시간/공간/사건/복선) | `GET .../canon?view=` | ✅ |

> 데모 계정으로 한 바퀴 돌리는 데 필요한 기능은 모두 존재한다.

## 부족한 점 (영향 큰 순서)

### 1. 프로젝트 카드의 썸네일·설명·작가를 채울 방법이 없음 — 실질적 공백
- **화면 근거:** 드라이브 카드의 제목·썸네일·Description·작가 아바타, 업로드 화면의 "작가: Cho" 메타.
- **현 상태:** `POST /projects`는 `name`만 받음. **프로젝트 수정 엔드포인트(PUT/PATCH) 없음.**
  `ProjectOut`에 `author`/`thumbnail_url`/`description` 칸은 있으나 입력·변경 경로가 없어 항상 비어 보임.
- **필요:** "프로젝트 수정" API + 썸네일(이미지) 업로드 처리.

### 2. 원문 업로드가 `.docx`를 못 받음
- **화면 근거:** "드래그&드롭(txt/docx)" 업로드 영역.
- **현 상태:** 업로드 파일을 utf-8 텍스트로 디코드만 함(`content.decode("utf-8")`).
  `.txt`는 정상, `.docx`(zip 바이너리)는 글자가 깨짐. spec 8장에서도 포맷 미확정.
- **필요:** 문서 파서(예: python-docx) 연동, 허용 포맷 확정.

### 3. 워크스페이스 "채팅 입력바 / + New Chats"에 대응하는 백엔드 없음
- **화면 근거:** 원문입력 뷰 하단 입력바 + 전송 버튼, 좌측 "+ New Chats".
- **현 상태:** 좌측 목록은 spec상 `GET /projects` 재사용이라 무방. 그러나 **하단 채팅 입력에 대응하는 API가 spec·코드 어디에도 없음.**
- **결정 필요:** 피그마 챗 템플릿 잔재인지, 실제 "원고 질의" 어시스턴트 기능인지. 후자라면 통째로 미구현.

### 4. 구독·공유 기능 미구현
- **구독:** 설정(⚙)의 "구독" → spec엔 `GET /me/subscription`이 "선택 범위"로만 존재, 실제 미구현. `User.plan` 필드만 있음.
- **공유:** Share 아이콘 / "내 공개 링크" → 백엔드 엔드포인트 없음, spec API 목록에도 없음. 공유가 실제 기능이면 설계 미존재.

### 5. 비밀번호 재설정이 껍데기(스텁)
- **화면 근거:** Forgot Password 화면.
- **현 상태:** `POST /auth/forgot-password`는 항상 "재설정 메일을 보냈습니다"만 반환. 실제 메일 발송·재설정 토큰·검증 없음 → 화면이 실제로 동작하지 않음.
- **필요(실서비스 시):** 메일 발송 + 재설정 토큰 발급/검증 흐름.

### 6. 자잘한 UI 요소
- **알림(Notification 아이콘):** 대응 알림 API 없음(장식 가능성).
- **회원가입 약관 동의 체크박스 / Remember me:** 백엔드 모델·로직 없음(토큰 만료 1440분 고정).
- **다크모드/테마(Sun 아이콘):** 프론트 전용 — 백엔드 공백 아님.

## 참고: UI와 무관한 내부 견고성 이슈 (별도 개선 항목)
- `is_current=true`가 항목당 1개임을 보장하는 **부분 유니크 인덱스(DB 레벨)** 부재 — 현재는 앱 코드에만 의존(동시 저장 시 이론적 위험, 순차 저장이라 실위험 낮음).
- 테스트가 외부 프로비저닝된 Postgres에 의존하고 **테스트 간 격리(롤백)·스키마 자동 생성**이 없음 → CI 자체 실행 어려움.

## 우선순위 제안
1. **(곧 필요)** 프로젝트 수정 API + 썸네일 업로드 — 화면 카드를 제대로 채우려면 필수.
2. **(곧 필요)** `.docx` 업로드 파싱 — 업로드 화면의 실제 사용성.
3. **(범위 결정)** 어시스턴트 챗 / 구독 / 공유 — 기능 포함 여부부터 확정.
4. **(실서비스 전)** 비밀번호 재설정 실동작화.
